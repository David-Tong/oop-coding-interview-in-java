# 支持撤销的栈式计算器

## 任务

使用 Java 17 实现一个支持数字输入、加法、减法和撤销的计算器，并编写自动化测试。本题考察代码正确性、边界处理和 OOP 设计，不要求界面、网络服务或持久化。

## 输入规则

输入是一串以英文逗号分隔的 token，按从左到右的顺序执行。允许 token 前后存在空白。

| token | 行为 |
| --- | --- |
| 非负十进制整数 | 输入一个数字 |
| `+` | 将最近的两个操作数相加 |
| `-` | 用较早的操作数减去较晚的操作数 |
| `U` | 撤销最近一次尚未被撤销的成功操作 |

输入数字在 Java `int` 的非负范围内，计算结果允许为负。假定运算结果不会溢出；不要求支持负数字面量、乘除法或 redo。

## 行为要求

- 数字输入、加法和减法均可以撤销。
- 撤销恢复该操作执行前的全部操作数；撤销本身不作为新的可撤销操作。
- 允许连续撤销，也允许撤销第一个数字，使操作数恢复为空。
- 撤销后可以继续执行新操作，后续操作不得影响更早的撤销结果。
- 单个操作失败时，操作数和撤销历史均保持执行前的状态，且允许继续接收操作。
- 对完整表达式求值时，遇到错误可以立即停止并抛异常。
- 全部 token 执行结束后，必须恰好剩余一个操作数，作为结果返回。
- 读取结果不能改变计算状态。
- 明确 API 的生命周期：重复求值应从独立状态开始；若选择一次性执行对象，应明确拒绝重复执行。

## 错误处理

以下情况应明确报错，消息需说明原因，不要求固定异常类型或文案：

- null、空字符串或空 token。
- 不支持的 token，或超出范围的输入数字。
- 加减运算时不足两个操作数。
- 没有可撤销的操作时执行撤销。
- 完整表达式执行结束后，操作数数量不为一个。

## 输入输出示例

输入：

```text
13, 5, +, 9, -, U, +
```

输出：

```text
27
```

## 交付要求

1. Java 17 实现与 JUnit 自动化测试。
2. 合理划分解析、运算、执行及撤销管理职责，并封装可变状态。
3. 简要说明设计取舍及时间、空间复杂度。

不强制使用特定设计模式、类名或容器。
