# 参考解决方案

对应题目：[支持撤销的栈式计算器](../problem/README.md)。本文给出一种设计方案，不限制其他满足要求的实现。

## 职责划分

| 对象 | 职责 |
| --- | --- |
| ExpressionParser | 校验输入并解析为普通操作或撤销指令 |
| Operation | 实现数字入栈、加法或减法，不管理历史 |
| OperandState | 封装操作数及复制、数量检查和结果读取 |
| Engine | 统一执行、保存历史、撤销及失败恢复 |
| Calculator | 为一次求值创建独立 Engine，调度指令并返回结果 |

普通操作只接收操作数接口，不接收整个 Engine，避免操作重新调度指令或修改历史。撤销作为控制指令由 Engine 处理，不要求它继承一个无法履行的普通操作接口。

## 状态与历史

使用操作数栈和历史栈。历史中保存每次成功普通操作之前的状态副本；撤销只消费历史，不新增历史。

普通操作的执行步骤：

```text
previous = current
candidate = copy(current)
operation.apply(candidate)
// 上一步失败则直接传播异常，current 和 history 均未修改
history.push(previous)
current = candidate
```

旧状态不再交给后续操作修改；恢复时也可以复制快照，保持历史与当前状态相互隔离。不能将仍保存在历史中的可变对象直接交给后续操作修改。

撤销步骤：

```text
if history is empty:
    报错，不修改状态
current = history.pop()
```

这种“保存执行前状态”的模型不需要预先将空状态加入历史。也可以保存执行后状态，但需保存初始空状态，并在撤销前检查历史至少有两个元素。两种模型不能混用。

## 解析与运算

- 先检查 null 和空白输入。
- 使用 `split(",", -1)` 保留末尾空 token，再逐项 trim、校验。
- 限定非负十进制整数并检查 int 范围。
- 运算前检查至少有两个操作数。
- 先弹出 right，再弹出 left；减法计算 `left - right`。
- 读取结果检查恰好一个操作数，使用 peek，不能 pop。
- 新的一次完整求值使用新 Engine，避免复用旧状态。

## 示例执行过程

从左到右表示栈底到栈顶：

```text
13  → [13]
5   → [13, 5]
+   → [18]
9   → [18, 9]
-   → [9]
U   → [18, 9]
+   → [27]
```

## 复杂度

设 token 数为 n，最大操作数栈深度为 d。完整快照方案执行普通操作需要 O(d) 时间与额外空间；撤销在转移快照所有权时为 O(1)，复制快照恢复时为 O(d)。整体最坏时间和历史空间均为 O(n²)，更一般可写为 O(n·d)。不要求为本题改成差量记录。
