# 4/10：只支持一步撤销的教学反例

来源：为学习新编写，不是用户早期代码。

## 统一评分与分级 Hire 判断

**统一评分：4/10。** 同一实现的分数不随目标级别改变，职级只影响本轮 Hire 判断。

| 目标级别 | 本轮判断 | 理由 |
| --- | --- | --- |
| Junior | No Hire | 连续撤销这一核心需求未完成。 |
| Senior | No Hire | 单步状态无法表达完整历史。 |
| Staff | No Hire | 执行和撤销规则不完整。 |
| Principal | No Hire | 问题模型尚不完整。 |

这是学习用的 coding + OOP 单轮判断，不是完整职级或最终录用结论。统一尺度和局限见 [评分总览](../README.md#统一评分与-hire-标准)。


## 如何验证

运行父目录 verify.py。对比“主示例通过”和“连续撤销失败”，理解只覆盖成功样例的局限。

## 升级方向

引入真正的历史栈，明确每个成功操作对应一条历史；决定保存操作前还是操作后状态，并始终遵守同一种模型。把撤销规则放在统一位置，而不是靠分支补丁修正。

## 设计学习点

一个 previous 变量能表达一步回退，不能表达任意次撤销。数据结构应匹配问题语义。抽取 parser 和执行器的价值在于让规则可以独立理解与验证，而不是为了凑类数。


## 测试来源与运行

本目录的 `src/test/java/calculator` 只保存作者测试。3、4 分为模拟作者测试；6、7 分根据对话重建；8 分保留原有断言。

评审测试统一位于 `../../solution/reviewer-tests`，不在本目录复制。默认运行作者测试；启用 `reviewer` profile 会额外加入共享评审测试。通用表达式测试适用于所有版本；依赖 Engine 扩展接口的测试只加入 6、7、8 分版本。

从仓库根目录运行本档作者测试：

```text
mvn -f simple-calculator/scores/4/pom.xml clean test
```

加入评审测试：

```text
mvn -f simple-calculator/scores/4/pom.xml -Previewer clean test
```

将 4 替换为本目录分数。低分版本或尚未满足严格边界的实现出现测试失败是预期的教学结果，不能修改断言迎合缺陷。
