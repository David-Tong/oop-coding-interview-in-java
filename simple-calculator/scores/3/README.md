# 3/10：主功能不完整的教学反例

来源：为学习新编写，不是用户早期代码。

## 统一评分与分级 Hire 判断

**统一评分：3/10。** 同一实现的分数不随目标级别改变，职级只影响本轮 Hire 判断。

| 目标级别 | 本轮判断 | 理由 |
| --- | --- | --- |
| Junior | No Hire | 基本减法和撤销尚未完成。 |
| Senior | No Hire | 核心功能不完整。 |
| Staff | No Hire | 尚未建立正确的状态模型。 |
| Principal | No Hire | 核心正确性与契约均不足。 |

这是学习用的 coding + OOP 单轮判断，不是完整职级或最终录用结论。统一尺度和局限见 [评分总览](../README.md#统一评分与-hire-标准)。


## 如何验证

运行父目录 verify.py。重点比较 `13, 5, -` 与完整主示例。不要因为 `13, 5, +` 输出 18 就认为核心功能完成。

## 升级到下一档

先写出左右操作数语义，修复减法；真正保存并恢复前一个状态，验证一次撤销。进一步必须支持多次撤销，不能止于主示例通过。

## 设计学习点

先保证规格正确，再讨论对象划分。单个方法本身不是低分理由；在这种规模下，一个职责清晰且完整正确的简单实现可以优于有很多类的错误实现。


## 测试来源与运行

本目录的 `src/test/java/calculator` 只保存作者测试。3、4 分为模拟作者测试；6、7 分根据对话重建；8 分保留原有断言。

评审测试统一位于 `../../solution/reviewer-tests`，不在本目录复制。默认运行作者测试；启用 `reviewer` profile 会额外加入共享评审测试。通用表达式测试适用于所有版本；依赖 Engine 扩展接口的测试只加入 6、7、8 分版本。

从仓库根目录运行本档作者测试：

```text
mvn -f simple-calculator/scores/3/pom.xml clean test
```

加入评审测试：

```text
mvn -f simple-calculator/scores/3/pom.xml -Previewer clean test
```

将 3 替换为本目录分数。低分版本或尚未满足严格边界的实现出现测试失败是预期的教学结果，不能修改断言迎合缺陷。
