# 分档实现与代码评审

这些目录用于比较同一道题的实现质量，评分维度固定为：功能正确性、状态与失败一致性、OOP 职责及封装、可读性和测试。类多、使用设计模式或代码短都不自动加分。

## 来源与评分口径

| 档位 | 来源 | Staff 本轮判断 | 核心学习点 |
| --- | --- | --- | --- |
| [3 分](3/README.md) | 新编写的反例 | No Hire | 主功能尚不完整，先保证计算语义 |
| [4 分](4/README.md) | 新编写的反例 | No Hire | 一个样例通过不等于完整实现撤销 |
| [6 分](6/README.md) | 按首次评审复原的 Command 持有快照版本 | No Hire | 命令与历史耦合、减法和失效测试 |
| [7 分](7/README.md) | 按 10:52 的 ExecutionContext 与双次撤销阶段复原 | No Hire | 保证失败时状态和历史同时不变 |
| [8 分](8/README.md) | 用户提供的实际源码，未修改 | Hire | 统一执行规则，并进一步收紧接口 |

6 分按用户指定的首次评审及对话源码复原，7 分按用户指定的 10:52 阶段复原；均非原始 Git 提交备份。对话出现过多个 6、7 分阶段，这里各选一个有代表性的阶段。3、4 分代码故意保留缺陷，请勿作为正确答案使用。

8 分沿用此前 coding + OOP 轮的统一质量评价。后来 problem 文档补充的严格空 token 等要求尚未全部实现，所以 8 分不表示通过当前完整验收，更不是对完整 Staff 职级的判断。其他版本也有局部做得更好的地方，例如 3、4 分版每次执行都创建新状态。

## 统一评分与 Hire 标准

每份实现只有一个统一的 10 分制质量分：评价功能正确性、状态和失败一致性、OOP 职责与封装、可读性和测试证据。目标职级不改变这个分数，只改变本轮是否 Hire 的判断。目录名就是统一评分，不再称为 Staff 专属评分。

本仓库采用以下学习尺度，并非通用招聘标准：

| 目标级别 | 本轮 Hire 参考线 | 主要期待 |
| --- | --- | --- |
| Junior | 6/10 | 基础实现与问题拆解能力，可在辅导下修复边界和设计问题 |
| Senior | 7/10 | 主功能和职责清晰，具备独立实现能力，仍可存在需要改进的失败契约 |
| Staff | 8/10 | 统一保证执行、历史与失败规则，能解释封装和扩展取舍 |
| Principal | 9/10 | 在本题规模内形成简洁、自洽且易验证的接口与状态模型，主动处理权限和生命周期契约 |

6 分版仍有明确功能缺陷，Junior Hire 表示这份材料展现的基础能力达到本仓库设定的培养门槛，不代表实现已满足题目验收。如果岗位要求完整正确交付作为硬性条件，该项可以直接导致 No Hire，不能机械套分数线。评分不会因增加类或设计模式而提高。

## 复现方法

在本目录运行：

```text
python verify.py
```

需要 Python 3 与 JDK 17 或以上，java 和 javac 需在 PATH 中。脚本在临时目录分别编译各档生产源码，再断言文档描述的行为；不写入源码目录，不依赖 Maven。

注意：脚本全部通过表示“各版本表现与记录一致”，包括故意失败的行为；不是所有版本都满足题目。脚本不替代 JUnit，也不执行 8 分目录现有的 JUnit 测试。各目录的 pom.xml 保留练习配置，未统一调整构建插件。

## 推荐学习顺序

1. 先不看评价，运行同一组输入，记录各版本差异。
2. 阅读对应 README，沿着失败路径跟踪操作数、历史和对象引用。
3. 在自己的分支修复问题，为每个问题添加回归测试。
4. 先建立状态规则，再优化类结构；避免仅仅增加类数。

状态规则：成功的普通操作新增一条历史；撤销消费历史；失败不改变状态与历史；后续修改不能污染历史；结果读取没有副作用。

## 作者测试与共享评审测试

`scores` 下只保留作者测试：3、4 分为模拟测试；6、7 分按对话重建；8 分为原有断言。独立评审测试只维护一套，位于 [solution/reviewer-tests](../solution/reviewer-tests/README.md)。

从仓库根目录运行 8 分作者测试及评审测试：

```text
mvn -f simple-calculator/scores/8/pom.xml -Previewer clean test
```

去掉 `-Previewer` 只运行作者测试；修改路径中的分数即可切换版本。使用 clean 避免旧 reviewer class 残留在 target/test-classes。

评审结果见 [TESTS.md](TESTS.md)。源码边界、API 差异和生命周期选择详见共享测试说明。
